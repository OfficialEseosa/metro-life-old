# R2 item 5: canvas object picking

New `frontend/src/scene/object-picking.tsx` exports the requested `PickTarget` type and `ObjectPicking({onPick})` component. Root integration must mount it inside the existing Canvas and pass the radial-menu/action callback. No existing source file, renderer composition, navigation data, store, movement code or API was edited by this subagent.

Native canvas pointer down/move/up events accept a primary left-button or touch tap with less than six pixels of movement. Six pixels or more, right orbit, non-primary/multitouch, pointer cancellation, HUD-originated gestures, and city/room/player changes during the gesture are rejected. The handler reads current store state at the tap, not a stale subscription. `screen` contains raw client coordinates for the overlay menu, including the actual canvas DOM offset. Listeners and callbacks clean up on unmount. There is no frame hook, frame React state, draw call or rendered pick mesh.

Indoor furniture uses analytical authored footprint/body boxes and use-seat proxies. IDs such as `table-2` remain intact for preferred-slot selection. `stationId` comes from authored slot/station data; the home chair maps to `couch`, a cafe reception counter maps to `counter`, and the small stadium/court display maps to `stands`. Slots on chairs rendered alongside tables/desks remain clickable. Decorative plants/shelves with no activity station do not become invented usable objects. Furniture `point` is the actual clicked body/seat XZ; the root must resolve that furniture's preferred slot/approach instead of always walking to the first generic table/desk station.

The open room doorway selects its visible actual jambs/lintel and exit floor region. It does not put an invisible solid panel across the opening. Door trim hidden by cutaway/down wall mode does not steal floor clicks. The returned door point is the authoritative room exit anchor, with `id` and `stationId` both `exit`.

People use the current visible `residents` instance matrices and `userData.ids`, matching exact current city/room and excluding self, offline humans and zero-scale instances hidden by camera clipping. This follows the actual displayed interpolated position even if its latest network position differs. If the batch has not mounted yet, the fallback uses effective activity/position data. Cosmetic counter staff have no authoritative social person ID and are represented by their usable counter.

Outside, actual landmark/home triangle hits become their doorway target, bypassing the scenery's disabled interaction raycast without mutating it. Gold arrival-pad and surveyed park-bench proxies remain clickable. Ground falls back to visible terrain triangles, an authored bridge-deck plane (above lower terrain), or valid land at zero elevation. Indoors only the current room floor/layout is considered; hidden mounted city groups never participate. The nearest usable hit wins; a nearer terrain/floor surface prevents proxy selection through the ground. Ground validity/pathfinding feedback remains the root movement controller's responsibility.

The existing `Pins` points object is named `map-pins`, with its index-to-location mapping recorded on geometry metadata. Before responding outdoors, ObjectPicking calls that object's real custom raycast, which already enforces `pinVisible`, cluster visibility and its 24-pixel hit radius. A foremost visible pin owns the click; a pin for the same doorway also owns its icon click even if a façade lies closer in 3D. This prevents a map selection from also opening an object menu or starting a walk. Unrelated nearer furniture/ground responses remain available. Hidden pins and all outdoor pins while indoors are ignored. Pin rendering, clustering, hover and R3F selection handlers are otherwise unchanged.

`node scripts/r2-item5-picking.cjs` executes the actual component against a CPU Three scene and a canvas event stub. It checks home stove/bed/shower/chair and exit mapping, open floor through hidden trim, touch input, drag/right/HUD/multitouch/cancel/context gates, specific food-hall table IDs, cafe ordering, actual resident matrices, clipped/wrong-room exclusion, disabled scenery raycasts, hidden landmark exclusion, park benches, bridge elevation, indoor/exterior isolation and listener cleanup. Results are saved to `item5-picking-check.json`. No WebGL or browser is used in this fixture.

Focused lint and read-only TypeScript semantic checking pass; no files were emitted. Root owns final integrated build and actual 1280x800/390px browser/menu/autowalk/queue checks. No GPU browser, Maven, build, local commit or other R2-item implementation was performed here.
